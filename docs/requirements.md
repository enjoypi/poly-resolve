# 业务需求

## 通用规则

- 渠道：支持命令行与服务两种渠道，同一功能在两种渠道下结果一致
- 身份：调用可附带会话与用户标识，用于留痕；对外服务时，标识只采信认证环节填写的，调用方自带的一律作废
- 访问范围：服务不直接对外开放，外部调用须先经认证再转交
- 留痕：每次调用记录渠道、会话、用户、功能、动作、请求、结果、成败、耗时；记录中不得出现密钥等敏感信息
- 停机：收到停机指令后不再受理新请求，已受理的请求处理完再结束；超过规定时长仍未完成则强制结束，并明确标示为超时结束；停机过程留痕
- 异常：
  - 请求无效：请求格式错误或不满足功能要求，拒绝处理
  - 功能不存在：所请求的功能或动作未提供，拒绝处理

## 健康检查

- 用途：探测服务是否可用
- 输入：无业务数据，附带内容忽略
- 输出：状态“正常”
- 规则：能处理请求即答“正常”，不检查下游系统
- 异常：请求格式错误时判为请求无效

## 消息采集

- 用途：持续收集钉钉消息，沉淀为统一的消息记录，供后续综合与决策；本功能只收集，不回复、不发送、不做 AI 决策
- 运行方式：可单独运行，也随服务同进程运行；随服务运行时，收集遇到须人工处理或存储失败则服务一并停止，并以对应退出码结束
- 范围：以登录员工本人的身份收集其可见的全部单聊与群聊消息；本人发出的消息不在实时通道内；上线前须取得员工授权与企业管理员开通
- 记录内容：来源、账号、会话、发送人、正文、发生时间（UTC）、收到时间（UTC）、原始内容
- 去重：同一来源、同一账号、同一消息只记一条，实时收集与补拉重叠时不重复
- 时间：钉钉返回的无时区时间按配置的固定时区换算为 UTC
- 密文：实时事件的正文可能是三方密文（单聊、群聊都有），判定规则与钉钉工具一致：多行 base64 正文加末尾“||版本||类型||长度”，正文不短于配置的长度；普通文字不算密文；密文入库前经钉钉工具解密；解密失败则按密文入库并留痕（不含正文）；补拉得到的明文不覆盖已入库的记录；停机时正在解密的事件不入库，下次启动的补拉会补回
- 转发消息：合并转发消息的正文里，被加密的子消息只留有截断的密文片段；入库前向钉钉工具查询其详情，正文重组为“标题行 + 每条子消息的 发送人:解密后内容”，查询失败则保持原样；实时收集与补拉都适用
- 补拉：启动与每次重连后，从已有记录的最新时间再往前回溯一段重叠时间，补拉到当前；无记录时回溯配置的时长；补拉失败或结果不完整不影响实时收集，仅留痕
- 异常：
  - 无法解析的消息：丢弃并留痕，留痕不含正文
  - 钉钉工具中断：自动重启，间隔逐次翻倍直到上限；曾收到消息的一轮结束后间隔复位
  - 登录失效或需授权：停止收集，以专用退出码提示人工处理，不再重试
  - 存储失败：停止收集，以专用退出码结束
- 停机：收到停机指令后先让钉钉工具正常退出再结束，超过规定时长则强行结束并留痕
- 留痕：只记数量、标识、长度与退出码，不记消息正文
- 存储：消息正文保存在本地数据库，保留期与脱敏规则待定

## 消息查看

- 用途：在页面上查看已收集的消息；只读，不改动、不发送
- 范围：只展示当前配置的来源与账号的消息；不展示原始内容
- 排序：按发生时间从新到旧；同一时间按消息键从大到小，保证翻页稳定
- 分页：每页条数可指定，缺省与上限取配置；超出上限或为 0 时拒绝；翻页用上一页给出的游标，没有更早的消息时不给游标
- 刷新：由使用者手动刷新或加载更早的消息，不自动推送
- 显示：每条含时间、发送人、会话与正文；发送人名为空时显示发送人标识；正文为空（非文本消息）时显示“[非文本消息]”；正文一律按纯文本显示
- 时间：库内为 UTC，页面按浏览器所在时区显示并标注偏移
- 异常：
  - 请求无效：游标格式错误、条数为 0 或超过上限、请求格式错误，拒绝处理
  - 存储不可用：消息库不存在或无法读取，返回“存储不可用”，不影响其他功能
- 留痕：请求与响应只记字节数，不记游标与消息正文
- 安全：页面与接口都会暴露消息正文，须置于认证之后
