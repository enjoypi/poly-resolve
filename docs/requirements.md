# 业务需求

## 通用规则

- 渠道：只经服务提供；页面与服务之间按资源与 HTTP 方法通信，接口说明由服务生成，页面据此调用
- 身份：调用可附带会话与用户标识，用于留痕；对外服务时，标识只采信认证环节填写的，调用方自带的一律作废
- 访问范围：服务不直接对外开放，外部调用须先经认证再转交；凡展示消息正文或待外发内容的页面与接口都在认证之后
- 授权：收集员工消息、把脱敏后的内容发往决策接口与 codex，上线前须取得员工授权与企业管理员同意
- 留痕：每次调用记录渠道、会话、用户、功能、动作、请求、结果、成败、耗时；任何留痕都不含密钥、消息正文、外发内容、提示词、分析结果与外部响应内容，涉及这些时只记数量、长度、标识与状态
- 停机：收到停机指令后不再受理新请求，已受理的请求处理完再结束；超过规定时长仍未完成则强制结束，并明确标示为超时结束；停机过程留痕
- 异常：
  - 请求无效：请求格式错误或不满足功能要求，拒绝处理
  - 功能不存在：所请求的功能或动作未提供，拒绝处理

## 健康检查

- 用途：探测服务是否可用
- 输入：无业务数据，附带内容忽略
- 输出：状态“正常”
- 规则：能处理请求即答“正常”，不检查下游系统

## 消息采集

- 用途：持续收集各数据源的消息，沉淀为统一的消息记录，供后续综合与决策；本功能只收集，不回复、不发送、不做决策
- 数据源：可配置多个，当前支持钉钉与邮箱（IMAP），将来接入其他 IM、RSS、消息队列等；各数据源同时收集、互不阻塞，各自补拉与重启；同类数据源的账号不得重复；以下各条除注明外均为钉钉的规则
- 运行方式：可单独运行，也随服务同进程运行；任一数据源遇到须人工处理或存储失败时，先让其余数据源正常停止，再以对应退出码结束
- 确认：需要向数据源确认已收到的（如消息队列的确认、邮件的已读标记），一律在入库成功之后确认
- 范围：以登录员工本人的身份收集其可见的全部单聊与群聊消息；本人发出的消息不在实时通道内
- 记录内容：来源、账号、会话、发送人、正文、发生时间（UTC）、收到时间（UTC）、原始内容
- 去重：同一来源、同一账号、同一消息只记一条，实时收集与补拉重叠时不重复
- 时间：钉钉返回的无时区时间按配置的固定时区换算为 UTC
- 补拉：启动与每次重连后，从已有记录的最新时间再往前回溯一段重叠时间，补拉到当前；无记录时回溯配置的时长；补拉失败或结果不完整不影响实时收集，仅留痕
- 密文判定：正文可能是三方密文（单聊、群聊都有），判定规则与钉钉工具一致，正文不短于配置的长度；普通文字不算密文；实时收集与补拉都先判定
- 解密：密文入库前经钉钉工具解密；解密失败（含超时）则按密文入库并留痕；补拉得到的明文不覆盖已入库的记录
- 启动自愈：每次启动时，库里最新的若干条密文消息（如此前解密失败的）重新解密并原地更新，数量有上限，仍失败的留待下次；解密成功的消息重新参与分级
- 转发消息：合并转发消息的正文里，被加密的子消息只留有截断的密文片段；入库前向钉钉工具查询其详情，正文重组为“标题行 + 每条子消息的 发送人:解密后内容”，查询失败（含超时）则保持原样；实时收集与补拉都适用
- 异常：
  - 无法解析的消息：丢弃并留痕
  - 钉钉工具中断：自动重启，间隔逐次翻倍直到上限并加随机抖动；曾收到消息的一轮结束后间隔复位
  - 登录失效或需授权：停止收集，以专用退出码提示人工处理，不再重试
  - 存储失败：停止收集，以专用退出码结束；消息库被其他写入暂时占用不算存储失败，稍后重试
- 解密并发：补拉与启动自愈时可同时解密多条，条数可配置
- 停机：先让钉钉工具正常退出再结束，超过规定时长则强行结束并留痕；正在解密或查询的消息不入库，下次启动的补拉会补回
- 存储：消息正文保存在本地数据库，保留期待定

### 邮箱

- 范围：每个邮箱的一个文件夹为一个数据源，可配多个；保持长连接实时收信，服务器不支持时定时检查；不收发件箱，本人的回复看不到
- 记录内容：会话按发件人划分；正文为主题加纯文本正文，只有网页正文时转成文字，引用的历史邮件截掉，附件只记类型与文件名，不保存附件内容；原始内容只留邮件标识、日期、发件人、主题、回复关系与服务器编号，不留收件人、抄送与投递路径
- 时间：以邮件到达服务器的时间为准，不用发件人自填的日期
- 不收：发件服务器认证（DMARC）未通过的、自动发送的、邮件列表与群发的；本人与别名发出的邮件入库但不参与决策
- 已读：不改变邮件的已读状态
- 去重：同一邮件只记一条；没有邮件标识的邮件在服务器重建文件夹编号后可能重复
- 补拉：启动与每次重连后，从最新邮件时间再往前回溯一段重叠时间（按日期，多回溯 1 天）补拉，单次数量有上限，超出时只取最新的
- 异常：连不上、超时、服务器断开都按间隔翻倍重连；收到过邮件或完整等过一轮新信的连接断开后间隔复位，登录后立刻断开的仍翻倍；密码被拒不停止其他数据源，按最长间隔重试并留痕；单封邮件过大只取前一部分，无法解析的丢弃并留痕
- 自检：启动时逐个邮箱登录再登出，失败则拒绝启动并说明是哪个账号、哪一步

## 消息查看

- 用途：在页面上查看已收集的消息；只读，不改动、不发送
- 范围：展示库里全部来源与账号的消息，可按来源筛选；不展示原始内容
- 排序：按发生时间从新到旧；同一时间的顺序固定，保证翻页稳定
- 分页：每页条数可指定，缺省与上限取配置；超出上限或为 0 时拒绝；翻页用上一页给出的翻页凭据，没有更早的消息时不给
- 时间范围：可按起止时间限定要看的消息，起止都可只给一端，起不晚于止；范围由系统筛选，对全部历史有效
- 刷新：由使用者手动刷新、加载更早的消息或加载全部，不自动推送；一次最多加载 2000 条，超过时提示缩小时间范围
- 显示：表格，默认列为时间、会话、发送人、正文、来源、账号，来源显示为类型（钉钉、邮箱，未知类型原样显示），其余字段（含将来新增的）自动成列；发送人名为空时显示发送人标识；正文为空（非文本消息）时显示“[非文本消息]”；会话标识对人不可读，用由标识生成的固定小图案区分，悬停与详情可看完整标识；内容过长时单元格截断，悬停可看完整内容，点击可看详情；每条正文提供复制按钮，复制完整原文
- 优先级与话题：已决策的消息显示优先级分数（0 至 1），默认显示；话题标识与高优先级话题的分析结果默认隐藏，详情里可看；未决策的为空
- 排序与筛选：任何字段都可排序与筛选（含将来新增的字段）；只作用于已加载的行，并如实标明已加载条数与是否还有更早的消息未加载；筛选词可要求整格精确匹配；点击某条消息的会话、发送人、来源或账号，只看对应的消息，可叠加，再点一次移除；每列标题上提供只清除该列筛选的按钮
- Markdown：详情里渲染标题、引用、代码块、粗体、行内代码与 http、https 链接，链接悬停提示不含地址里的查询参数；列表、表格、图片、HTML 不渲染，按原文显示；表格单元格里只显示去掉标记的纯文本
- 设备：桌面与手机都可用，尽量铺满屏幕；深色、简约科幻风格；字号最多 4 种，桌面正文 14 号；网站图标为深色底、浅紫色 “PR” 字母
- 时间：库内为 UTC，页面按浏览器所在时区显示并标注偏移
- 异常：
  - 请求无效：翻页凭据格式错误、条数为 0 或超过上限、请求格式错误，拒绝处理
  - 存储不可用：消息库不存在或无法读取，返回“存储不可用”，不影响其他功能
- 留痕：请求与响应只记字节数

## 消息分级与转交

- 用途：把全部未处理的消息成批交给决策接口，得到每条消息的优先级，并把不同会话里说同一件事的消息归为同一话题；高优先级话题的对话交给 codex 做只读分析，分析结果存库并发给本人
- 运行方式：随服务同进程运行，有总开关；开启后新入库的消息自动脱敏后排队，自动通过模式下自动成批，人工审核模式下由使用者点“审核”取批，决策与转交失败不影响消息收集与服务运行，也不使服务退出；成批与决策、分析与通知各自运行，分析耗时不阻塞成批与决策
- 范围：首次开启只处理回溯时长内的消息；之后停机或关闭开关期间到达的消息，再开启时接着处理，最远补到积压上限，更早的不处理；决策时已超过回溯时长的消息只打分不转交；每条消息只外发一次；每批条数有上限；自动通过模式下补积压时先处理最旧的，新旧消息都处理、不遗漏，上一批封批后即可开始下一批的筛查；人工审核模式下每次点“审核”取排队中最新的一批，上一批审完即可再取，未取到的较早消息留在队列，不保证处理，也不清理；下一批要等上一批外发结束（已决策或重试用尽记为失败）才封批外发，任何时候只外发一批，全被拒绝的批不必等待；以下消息不外发、不决策，只记为已跳过：本人发出的、发往通知会话的、正文为空的、仍是密文的；本人、通知会话与密文按消息所属数据源判定，没有这些概念的数据源不判定
- 流程：规则脱敏 → 本地模型筛查（可选）→ 外发审核 → 决策 → codex 分析 → 通知本人
- 话题：话题与 codex 会话一一对应，使用同一个标识；同一会话内相邻消息的间隔不超过设定时长算同一段，该会话已有开放话题时新消息直接并入；其余的段由决策接口在“已有话题、本批更早的段、新话题”中选一个；答案缺失、被拒答、置信度不足一律当新话题；话题空闲超过设定时长即关闭；话题的优先级取成员消息的最高分，只用于展示；是否转交只看本批新消息的最高分，话题此前的高分不再触发转交；不合并、不拆分话题，一个会话里交错的两件事会并成一个话题
- 脱敏：外发前先脱敏；发送人只写名字，不外发发送人标识；密钥与凭据（私钥、各平台令牌、认证头与 Cookie、带密码的连接串、“密码”“口令”“验证码”等词后面的值、长随机串）、所有链接与地址、文件路径与密钥文件名、手机号、身份证、银行卡、邮箱一律换成占位符，文件、图片、语音消息只留类型；人名、公司名不处理；规则可配置，规则无效则服务启动失败、不外发；脱敏只降低暴露，不替代授权，不保证拦住全角变体、拆在两条消息里的密钥与被编码的密钥
- 审核：取进批的每条消息先经外发审核（见“外发审核”），一批里没有待审的消息才外发，只外发已通过的；审核没有期限，一批不审完就一直等；漏脱敏的拒绝让系统学出新的脱敏规则，该条重新脱敏后回到待审，此后每条消息外发前都再套一遍全部规则，已封批但还没外发的批在外发前按当时全部规则（含配置变更）重新生成，外发的话题说明也按当时规则重新生成；学到的规则不经任何接口与日志返回，只能拦住完全相同的文字，泛化要由使用者改配置；通过后到发出之间内容只会比使用者看到的遮得更多；审核方式可配置为自动通过，规则成熟后切换，只改配置
- 决策：一个请求里对每条消息提一个是非问题（这条消息所在的对话按最新进展是否需要尽快处理），取返回的概率作为优先级分数；分数不低于阈值为高优先级；再对每个需要归属的段提一个选择题（属于哪个话题）；外发的只有脱敏后的文字与别名，不含发送人标识、会话标识与消息标识；接口地址、模型、问题文本、阈值、置信度下限都可配置；问题数与选项数受接口上限约束，超过时服务启动失败；返回的答案数量或类型不符按失败重试，单个答案缺失或被拒答只让该条无优先级或另起话题
- 转交：高优先级话题的对话交给 codex，提示词只含已通过审核的文本，不再有第二道审核；codex 只读：不改文件、不发消息、不联网；消息内容视为不可信数据，其中的指令一律不执行；同一话题的后续分析延续同一个 codex 会话，只补充新增消息，话题空闲过久或续写失败则新建会话；codex 的会话文件含脱敏后的对话，保留期待定
- 结果：分析结果存库，页面在对应消息上显示优先级、话题与分析；同时发到本人指定的会话，通知含话题标签、本次触发转交的分数与分析结果，发送带幂等标识，重试不会重复送达
- 防自循环：通知发往的会话与本人发出的消息都不再决策，发出的通知被再次收集后不会触发新一轮
- 限额：每小时决策请求数、每小时转交次数、同一话题两次转交的最短间隔都有上限，用完后新消息等下一个窗口；同一话题只保留一个尚未开始分析的转交，后到的并入并刷新时间；排队的转交新的先出；话题关闭后尚未分析的转交不再发出；没有可外发消息的批不计入；一批只外发一次，重启不重复
- 重试：筛查、决策、分析、通知失败（含超时）后等待再试，等待从初始间隔起逐次翻倍直到上限并加随机抖动，每次重试留痕对象、次数、原因与等待时长；决策、分析、通知达到次数上限后记为失败，筛查不设上限；消息库读写失败或规则无效时整轮处理同样逐次翻倍等待，恢复后复位；失败的决策批隔一段时间（逐轮翻倍）自动再来一轮，轮数有上限，用完后可在页面上手动重发（见“外发审核”）；分析失败只重试分析，发送失败只重试发送，不重复分析；每次调用前先记下一次尝试，记不下则不调用；决策接口的答复先存再用，存下后即使后续写库失败也不再重复外发；停机时在途的调用被中断、不计次数，下次启动接着做
- 异常：所需的环境变量缺失时，开关开启的服务启动即失败；开关开启时，启动先确认能连上决策接口与 codex 的模型接口（只建连接，不发请求），连不上则启动失败；其余失败只留痕
- 安全：接口地址、代理地址与密钥只经环境变量提供，不进配置文件与日志；codex 使用专用的空目录、专用的认证与独立的环境，不接触本机其他凭据与配置

## 本地模型筛查

- 用途：规则脱敏之后、外发审核之前，用使用者自备的本机小模型再筛一遍，补漏规则没拦住的密钥，并给出每条消息可能属于哪些已有话题；可选，缺省不启用
- 范围：每条取进批的消息，逐条送给模型、可同时筛查多条；模型只能多遮，不能少遮，不能决定放行，也不替代人工审核
- 规则：模型指出的片段必须是该条文字的原文且不短于设定长度才会被遮盖；判为高风险却给不出可遮盖的片段的消息会被标出，人工审核时置顶高亮，自动通过模式下直接排除；话题候选必须是当前开放的话题，只用于缩小决策接口的选项范围
- 异常：某条消息筛查失败（模型不可达、超时、返回无法解析或没有给出该条的判断）只重试这一条，其余照常；批内还有未筛完的消息时该批不外发，不放行任何未筛的消息；所需的环境变量缺失时，开关开启的服务启动即失败
- 漏判样本：以下三种情形把该条当时的文字（已过规则脱敏）与相关片段存进本机消息库，供日后改进规则与提示词：模型遮住了规则没拦住的片段；模型判为高风险却给不出片段；人工以漏脱敏拒绝。样本不经任何接口与日志返回，保留期待定
- 安全：模型只在本机运行，只允许连本机端口，不经代理；它可能漏判，故不能当作授权依据

## 外发审核

- 用途：在页面上逐条检查待外发的消息并通过或拒绝；不改动内容；单人使用，不记录审核人
- 取批：点“审核”把排队中最新的一批（条数同每批上限）取进待审；还有待审或筛查中的消息时不能再取；配了本地模型时先筛查，完成后刷新才出现；没有排队的消息时提示“暂无新消息”；自动通过模式下没有此操作
- 显示：每项显示批号、来源与账号、会话、发送人、时间与外发的脱敏文字原文；内容只按纯文本显示，不渲染，其中的脱敏占位符标红（原文里恰好有与占位符相同的文字也会标红；替换为空的规则删掉的文字无从标出）；列出全部待审核项和待审数，没有时提示“没有待审核项”；有待审项时提供“整批通过”，逐条通过当前列出的全部，遇到失败即停
- 操作：通过，或选一个原因后拒绝；漏脱敏类原因须粘贴漏掉的原文，提交后输入框立即清空、原文不回显；其余原因即排除，该条不外发；已被处理的项不能改判：同一裁决重复提交原样返回当前状态，不同裁决拒绝
- 异常：
  - 请求无效：请求格式错误
  - 违反审核规则：拒绝原因不在配置里、粘贴的原文过短或不在该条文字里、原因与是否粘贴不匹配
  - 审核项不存在
  - 已作不同裁决：该项已被处理且与本次裁决不同
  - 不能取批：还有未审完的消息，或不是人工审核模式
  - 存储不可用：库不存在或无法读取，返回“存储不可用”
- 失败批：另一页列出决策重试用尽的批（批号、时间、尝试次数、已通过条数、失败原因），可逐批重发，重发即再给一轮重试；已有批在外发时不能重发
- 留痕：请求与响应只记字节数

## 提示词

- 用途：在页面上查看并改写发给 AI 的提示词：codex 分析的首次与续写提示词、决策接口的紧急判断与话题归属问题、本地模型筛查的系统提示（配了筛查才有）
- 存放：每个提示词一个文件，放在配置的目录下；页面保存即改写该文件，改动可用版本库追溯与提交
- 生效：每次调用时读取文件，保存后下一次调用生效，已发出的调用不受影响；已封批未外发的批在外发前按新问题重新生成
- 校验：正文不能为空；必含的占位符（分析提示词的消息位置、紧急判断的消息别名、话题归属的段别名）须恰好出现一次；页面实时标出缺失的占位符，不合规时不能保存
- 异常：名字不存在或该提示词未启用；不合规；存储不可用；启动时任一提示词缺失或不合规则启动失败；运行中读不到或不合规时该次调用失败，按重试规则重来，不发出不合规的提示词
- 编辑：每项可撤销未保存的修改；有未保存修改时离开页面需确认；不做并发冲突检测，后保存的覆盖先保存的
- 留痕：只记名字与长度，不记正文

## 外部调用隔离

- 用途：消息收集、分析与通知所调用的外部命令（钉钉工具、codex）以最小权限运行；决策、本地模型与邮箱通过进程内网络连接调用（不经外部命令隔离），即使被消息内容诱导，也读不到本机其他凭据与文件
- 范围：外部命令只能访问自己必需的目录、网络端口与系统服务，不能读写消息库、加密的密钥文件与版本库；HTTP 客户端不跟随重定向，不读系统与环境中的代理设置；决策使用 HTTPS 或回环 HTTP，本地模型只允许回环 HTTP 与显式端口；决策接口、每个邮箱与每个外部命令可各配一个代理，代理只能是带显式端口、无认证信息的本机 HTTP 或 SOCKS5 地址；邮箱只允许加密连接，本机明文例外且不得配代理；决策只有 HTTPS 地址才经代理，经代理时仍校验目标主机的证书，代理不可用时不改为直连；配了代理的外部命令只能连该代理端口
- 异常：HTTP 地址、代理地址或环境变量配置无效时服务拒绝启动；外部命令启动自检不通过时服务拒绝启动并说明是哪条命令；运行中调用被拒绝按对应功能失败处理
- 留痕：外部调用记录渠道、会话、用户、功能、动作、请求与响应字节数、状态、次数与耗时，不记录接口地址、代理地址、密钥、消息正文、提示词、分析结果或外部响应内容；自检失败原因写标准错误
- 局限：外部命令的网络只能按端口限制，不能按域名限制；钉钉工具须读取其登录凭据；所用的系统隔离机制已被系统标为弃用；配了代理时，外部命令经代理能到达哪些目标由代理决定，代理须拒绝连往本机与内网地址，否则外部命令可经代理访问本服务与本地模型；代理能看到连接的目标主机、端口与流量大小，看不到密钥与内容；外部命令是否遵守代理设置须使用者实测；规则是否完整，须使用者在真实环境逐条验证
