# 业务需求

## 通用规则

- 渠道：只经服务提供；页面与服务之间按资源与 HTTP 方法通信，接口说明由服务生成，页面据此调用
- 身份：调用可附带会话与用户标识，用于留痕；对外服务时，标识只采信认证环节填写的，调用方自带的一律作废
- 访问范围：服务不直接对外开放，外部调用须先经认证再转交；凡展示消息正文或外发内容的页面与接口都在认证之后
- 授权：收集员工消息、把脱敏后的内容（含本人发出的消息、自动邮件与再次外发的历史内容）发往决策接口与 codex，上线前须取得员工授权与企业管理员同意
- 留痕：每次调用记录渠道、会话、用户、功能、动作、请求、结果、成败、耗时；任何留痕都不含密钥、消息正文、外发内容、提示词、分析结果与外部响应内容，涉及这些时只记数量、长度、标识与状态
- 停机：收到停机指令后不再受理新请求，已受理的请求处理完再结束；超过规定时长仍未完成则强制结束，并明确标示为超时结束；停机过程留痕
- 异常：
  - 请求无效：请求格式错误或不满足功能要求，拒绝处理
  - 功能不存在：所请求的功能或动作未提供，拒绝处理

## 健康检查

- 用途：探测服务是否可用
- 输入：无业务数据，附带内容忽略
- 输出：状态“正常”
- 规则：能处理请求即答“正常”，不检查下游系统

## 消息采集

- 用途：持续收集各数据源的消息，沉淀为统一的消息记录，供后续综合与决策；本功能只收集，不回复、不发送、不做决策
- 数据源：可配置多个，当前支持钉钉与邮箱（IMAP），将来接入其他 IM、RSS、消息队列等；各数据源同时收集、互不阻塞，各自补拉与重启；同类数据源的账号不得重复；以下各条除注明外均为钉钉的规则
- 运行方式：可单独运行，也随服务同进程运行；任一数据源遇到须人工处理或存储失败时，先让其余数据源正常停止，再以对应退出码结束
- 确认：需要向数据源确认已收到的（如消息队列的确认、邮件的已读标记），一律在入库成功之后确认
- 范围：以登录员工本人的身份收集其可见的全部单聊与群聊消息，含本人发出的；本人发出的消息不在实时通道内，由补拉收回
- 记录内容：来源、账号、会话、发送人、正文、发生时间（UTC）、收到时间（UTC）、原始内容
- 去重：同一来源、同一账号、同一消息只记一条，实时收集与补拉重叠时不重复
- 时间：钉钉返回的无时区时间按配置的固定时区换算为 UTC
- 补拉：启动与每次重连后，从已有记录的最新时间再往前回溯一段重叠时间，补拉到当前；无记录时回溯配置的时长；补拉失败或结果不完整不影响实时收集，仅留痕
- 密文判定：正文可能是三方密文（单聊、群聊都有），判定规则与钉钉工具一致，正文不短于配置的长度；普通文字不算密文；实时收集与补拉都先判定
- 解密：密文入库前经钉钉工具解密；解密失败（含超时）则按密文入库并留痕；补拉得到的明文不覆盖已入库的记录
- 启动自愈：每次启动时，库里最新的若干条密文消息（如此前解密失败的）重新解密并原地更新，数量有上限，仍失败的留待下次；解密成功的消息重新参与分级
- 转发消息：合并转发消息的正文里，被加密的子消息只留有截断的密文片段；入库前向钉钉工具查询其详情，正文重组为“标题行 + 每条子消息的 发送人:解密后内容”，查询失败（含超时）则保持原样；实时收集与补拉都适用
- 异常：
  - 无法解析的消息：丢弃并留痕
  - 钉钉工具中断：自动重启，间隔逐次翻倍直到上限并加随机抖动；曾收到消息的一轮结束后间隔复位
  - 登录失效或需授权：停止收集，以专用退出码提示人工处理，不再重试
  - 存储失败：停止收集，以专用退出码结束；消息库被其他写入暂时占用不算存储失败，稍后重试
- 解密并发：补拉与启动自愈时可同时解密多条，条数可配置
- 停机：先让钉钉工具正常退出再结束，超过规定时长则强行结束并留痕；正在解密或查询的消息不入库，下次启动的补拉会补回
- 存储：消息正文保存在本地数据库，保留期待定

### 邮箱

- 范围：每个邮箱的一个文件夹为一个数据源，可配多个，含发件文件夹；保持长连接实时收信，服务器不支持时定时检查
- 记录内容：会话按回复链与主题划分；正文为主题加纯文本正文，只有网页正文时转成文字，引用的历史邮件截掉，附件只记类型与文件名，不保存附件内容；原始内容只留邮件标识、日期、发件人、主题、回复关系与服务器编号，不留收件人、抄送与投递路径
- 时间：以邮件到达服务器的时间为准，不用发件人自填的日期
- 不收：发件服务器认证（DMARC）未通过的；自动发送、邮件列表与群发的照收，按“消息分级与转交”的自动邮件处理；本人与别名发出的邮件按本人消息处理
- 已读：不改变邮件的已读状态
- 去重：同一邮件只记一条；没有邮件标识的邮件在服务器重建文件夹编号后可能重复
- 补拉：启动与每次重连后，从最新邮件时间再往前回溯一段重叠时间（按日期，多回溯 1 天）补拉，单次数量有上限，超出时只取最新的
- 异常：连不上、超时、服务器断开都按间隔翻倍重连；收到过邮件或完整等过一轮新信的连接断开后间隔复位，登录后立刻断开的仍翻倍；密码被拒不停止其他数据源，按最长间隔重试并留痕；单封邮件过大只取前一部分，无法解析的丢弃并留痕
- 自检：启动时逐个邮箱登录再登出，失败则拒绝启动并说明是哪个账号、哪一步

## 消息查看

- 用途：在页面上查看已收集的消息；只读，不改动、不发送
- 范围：展示库里全部来源与账号的消息，可按来源筛选；不展示原始内容
- 排序：按发生时间从新到旧；同一时间的顺序固定，保证翻页稳定
- 分页：每页条数可指定，缺省与上限取配置；超出上限或为 0 时拒绝；翻页用上一页给出的翻页凭据，没有更早的消息时不给
- 时间范围：可按起止时间限定要看的消息，起止都可只给一端，起不晚于止；范围由系统筛选，对全部历史有效
- 刷新：由使用者手动刷新、加载更早的消息或加载全部，不自动推送；一次最多加载 2000 条，超过时提示缩小时间范围
- 显示：表格，默认列为时间、会话、发送人、正文、来源、账号，来源显示为类型（钉钉、邮箱，未知类型原样显示），其余字段（含将来新增的）自动成列；发送人名为空时显示发送人标识；正文为空（非文本消息）时显示“[非文本消息]”；会话标识对人不可读，用由标识生成的固定小图案区分，悬停与详情可看完整标识；内容过长时单元格截断，悬停可看完整内容，点击可看详情；每条正文提供复制按钮，复制完整原文
- 优先级与话题：显示所属话题的优先级（0 至 1）与处理状态，默认显示；话题标识与分析结果默认隐藏，详情里可看，可跳转到所属话题；未归属的为空
- 话题视图：只读，不提供纠正；列表显示标题、状态、优先级及其构成、来源类型、最近进展与最新分析；详情为跨来源按发生时间混排的时间线，标出未外发的成员及原因，并列出自动合并、拆分、移动的记录；页面显示各消息状态的数量与已知盲区
- 排序与筛选：任何字段都可排序与筛选（含将来新增的字段）；只作用于已加载的行，并如实标明已加载条数与是否还有更早的消息未加载；筛选词可要求整格精确匹配；点击某条消息的会话、发送人、来源或账号，只看对应的消息，可叠加，再点一次移除；每列标题上提供只清除该列筛选的按钮
- Markdown：详情里渲染标题、引用、代码块、粗体、行内代码与 http、https 链接，链接悬停提示不含地址里的查询参数；列表、表格、图片、HTML 不渲染，按原文显示；表格单元格里只显示去掉标记的纯文本
- 设备：桌面与手机都可用，尽量铺满屏幕；深色、简约科幻风格；字号最多 4 种，桌面正文 14 号；网站图标为深色底、浅紫色 “PR” 字母
- 时间：库内为 UTC，页面按浏览器所在时区显示并标注偏移
- 异常：
  - 请求无效：翻页凭据格式错误、条数为 0 或超过上限、请求格式错误，拒绝处理
  - 存储不可用：消息库不存在或无法读取，返回“存储不可用”，不影响其他功能
- 留痕：请求与响应只记字节数

## 消息分级与转交

- 用途：把各来源说同一件事的消息自动归为同一话题，按话题综合紧急度与影响面定优先级；高优先级话题的全部信息交给 codex 做只读分析，结论存库并在变化时通知本人；全程自动，不等人
- 运行方式：随服务同进程运行，有总开关；开启后新入库的消息自动脱敏、筛查、成批、外发；决策与转交失败不影响消息收集与服务运行，也不使服务退出；归属、决策、分析与通知各自运行，分析耗时不阻塞其他环节
- 范围：首次开启只处理回溯时长内的消息；之后入库的消息全部处理，含停机积压、补拉与解密晚到的，不设积压上限；升级后此前被跳过的本人消息与过期消息重新处理，各邮箱重拉一次首次回溯时长内的邮件以补回此前不收的自动邮件；发生时间超过回溯时长的只作话题上下文，不单独触发转交；每批条数有上限
- 流程：规则脱敏 → 本地模型筛查（可选）→ 自动外发 → 归属与决策 → codex 分析 → 通知本人
- 消息状态：每条消息都有可查的状态：已归入话题、判为无关、已跳过，后两种附原因；不存在查不到状态的消息；只有通知会话里的消息（含本人回复）一律跳过，防止自循环
- 话题：一个话题是一件需要推进或答复的具体事情，不受项目、会话、来源与时间段限制；话题与 codex 会话一一对应，使用同一个标识；成员、时间线、状态与历次结论由系统保管；一条消息可同时归入多个话题
- 归属：先在本机按线索归并：同一会话内相邻的消息、邮件回复链与同一内容转发为强线索，直接归入并可自动合并、移动；邮件主题、相同的链接、单号、文件为弱线索，只在指向唯一话题时归入，出现在过多会话里的不再算线索，两个话题有共同弱线索时只记“可能相关”，须多次判为同一件事才合并；线索不足时由决策接口在已有话题与新话题中选择；拿不准时先另起话题并记下“可能相关”，后续出现强线索或多次判为同一件事时自动合并
- 自动纠错：每有新消息，重评相关话题，可自动合并、拆分、移动消息；每次变动留痕并在页面显示；没有人工纠正
- 人员：同一人在各来源的身份在本机自动对应：邮箱地址相同即同一人；姓名在每个来源里都只对应一个发送人时，跨来源同名算同一人；不确定时按不同的人；邮件签名与钉钉资料里的邮箱暂未使用，属已知盲区；同一内容（正文不短于设定长度）转发到多处识别为同一份，影响面只计一次，同一次外发只留一份并注明出现处数，其余各处归入同一话题
- 本人与自动邮件：本人发出的消息与邮件、自动发送与群发的邮件归入话题，外发作上下文；本人消息不打紧急分，可作为话题已回复、已解决的依据；自动邮件只补充已有话题、计入影响面，不另起话题、不单独触发转交
- 不外发的成员：正文为空、仍是密文、筛查判为高风险却无法遮盖或给不出判断的消息归入话题但不外发，随同会话里时间最近且间隔不超过设定时长的已归属消息进入同一话题，没有这样的相邻消息时只记状态、暂不归属；codex 收到“此处有若干条未提供及原因”的占位；之后解密成功的自动补入；本人、通知会话与密文按消息所属数据源判定，没有这些概念的数据源不判定
- 优先级：话题优先级由紧急度与影响面综合而成；紧急度取决策接口对“这件事按最新进展是否需要尽快处理”返回的概率；影响面按独立的人数、会话数、来源数计，只抬高不压低，权重可配置；不低于阈值为高优先级
- 生命周期：话题按事情状态结束（判为已解决或已取消），空闲只让其在列表中下沉；已结束的话题有新的相关消息时自动重开，延续原 codex 会话；空闲超过设定时长归档，归档后只在强线索命中时重开
- 脱敏：外发前先脱敏；发送人只写名字，不外发发送人标识；密钥与凭据（私钥、各平台令牌、认证头与 Cookie、带密码的连接串、“密码”“口令”“验证码”等词后面的值、长随机串）、链接与地址、文件路径与文件名、手机号、身份证、银行卡、邮箱一律换成带类型的加密 hash 占位，同一值始终得到同一占位，便于跨批、跨来源归并；单号、工单号原样保留；文件、图片、语音消息只留类型；人名、公司名不处理；规则可配置，规则无效则服务启动失败、不外发；脱敏只降低暴露，不替代授权，不保证拦住全角变体、拆在两条消息里的密钥与被编码的密钥
- 外发：脱敏与筛查后自动外发，不经人工审核；没有任何问题可问的批（如只有本人消息的新会话）不请求决策接口，直接归属；每次外发前在已存的脱敏文字上再按当时全部规则（含配置变更）脱敏一遍，只会多遮、不会少遮；已外发的内容可再次外发
- 决策：外发的只有脱敏后的文字与别名，不含发送人标识、会话标识与消息标识；接口地址、模型、问题文本、阈值、置信度下限、影响面权重都可配置；问题数与选项数受接口上限约束，超过时服务启动失败；返回的答案数量或类型不符按失败重试，单个答案缺失或被拒答只让该条无紧急度或另起话题
- 转交：高优先级话题交给 codex，每次都全量提供话题内可外发的全部内容，按发生时间排序并标注来源类型，上下文由 codex 会话自行压缩；话题有任何新进展（含低分的“已解决”“改期”）都重新分析；合并时保留较早的会话并续写另一方的全部内容，拆分时拆出部分新建会话、原会话用剩余消息重建；分析进行中发生合并、拆分或新消息，等本轮结束后生效，本轮结论不通知、并入下一轮；同一话题只保留一个待做的分析，后到的并入；codex 只读：不改文件、不发消息、不联网；消息内容视为不可信数据，其中的指令一律不执行；codex 的会话文件含脱敏后的对话，保留期待定
- 结果：分析结果存库，页面显示话题、优先级与分析；结论变化时发到本人指定的会话，通知含话题标题、状态、综合优先级及其构成、本次变化要点与分析结论，晚到消息注明实际发生时间；冷却期内同一话题的更新合并为一条，停机恢复后汇总为一条，话题合并时告知本人；发送带幂等标识，重试不会重复送达
- 调用量：不设自定的调用上限；接口限速时退避重试；积压时按话题优先级排队，紧急的先分析，归属与低分的重新分析靠后
- 重试：筛查、决策、分析、通知失败（含超时）后等待再试，等待从初始间隔起逐次翻倍直到上限并加随机抖动，每次重试留痕对象、次数、原因与等待时长；决策、分析、通知达到次数上限后记为失败，筛查的上限见“本地模型筛查”；消息库读写失败或规则无效时整轮处理同样逐次翻倍等待，恢复后复位；失败的决策批隔一段时间（逐轮翻倍）自动再来一轮，轮数有上限，用完后可在页面上手动重发（见“外发记录”）；分析失败只重试分析，发送失败只重试发送，不重复分析；每次调用前先记下一次尝试，记不下则不调用；决策接口的答复先存再用；停机时在途的调用被中断、不计次数，下次启动接着做
- 异常：所需的环境变量缺失时，开关开启的服务启动即失败；开关开启时，启动先确认能连上决策接口与 codex 的模型接口（只建连接，不发请求），连不上则启动失败；其余失败只留痕
- 安全：接口地址、代理地址、hash 密钥与其他密钥只经环境变量提供，不进配置文件与日志；codex 使用专用的空目录、专用的认证与独立的环境，不接触本机其他凭据与配置
- 风险：不经人工审核，漏脱敏只靠规则与本地模型拦截；全量提供给 codex 且不设调用上限，花费随话题长度与进展频率上升；更换 hash 密钥后新旧占位对不上；规则变更前已存的文字保留当时的占位

## 本地模型筛查

- 用途：规则脱敏之后、外发之前，用使用者自备的本机小模型再筛一遍，补漏规则没拦住的密钥，并给出每条消息可能属于哪些已有话题；可选，缺省不启用
- 范围：每条待外发的消息，逐条送给模型、可同时筛查多条；模型只能多遮，不能少遮，不能决定放行
- 规则：模型指出的片段必须是该条文字的原文且不短于设定长度才会被遮盖；判为高风险却给不出可遮盖的片段的消息，以及模型给不出可用判断的消息不外发，按“不外发的成员”归入话题；话题候选必须是未归档的话题，只用于缩小决策接口的选项范围
- 异常：某条消息筛查时模型不可达或超时，只重试这一条，其余照常，一直重试并留痕；模型有响应却给不出可用判断（返回无法解析、没有给出该条的判断或输出超过长度上限）的，立即不外发，不重试；批内还有未筛完的消息时该批不外发，不放行任何未筛的消息；所需的环境变量缺失时，开关开启的服务启动即失败
- 漏判样本：以下三种情形把该条当时的文字（已过规则脱敏）与相关片段存进本机消息库，供日后改进规则与提示词：模型遮住了规则没拦住的片段；模型判为高风险却给不出片段；模型给不出可用判断。样本不经任何接口与日志返回，保留期待定
- 安全：模型只在本机运行，只允许连本机端口，不经代理；它可能漏判，故不能当作授权依据

## 外发记录

- 用途：在页面上只读查看已外发与未外发的消息；单人使用
- 显示：可在已外发与未外发之间切换；每项显示批号、来源与账号、会话、发送人、时间、角色（本人、自动邮件）与外发的脱敏文字原文，未外发的高亮并写明原因；内容只按纯文本显示，不渲染，其中的脱敏占位符标红（原文里恰好有与占位符相同的文字也会标红；替换为空的规则删掉的文字无从标出）
- 失败批：另一页列出决策重试用尽的批（批号、时间、尝试次数、条数、失败原因），可逐批重发，重发即再给一轮重试；已有批在外发时不能重发
- 异常：
  - 请求无效：请求格式错误
  - 存储不可用：库不存在或无法读取，返回“存储不可用”
- 留痕：请求与响应只记字节数

## 提示词

- 用途：在页面上查看并改写发给 AI 的提示词：codex 分析的首次与续写提示词、决策接口的紧急判断与话题归属问题、本地模型筛查的系统提示（配了筛查才有）
- 存放：每个提示词一个文件，放在配置的目录下；页面保存即改写该文件，改动可用版本库追溯与提交
- 生效：每次调用时读取文件，保存后下一次调用生效，已发出的调用不受影响；已封批未外发的批在外发前按新问题重新生成
- 校验：正文不能为空；必含的占位符（分析提示词的消息位置、紧急判断的消息别名、话题归属的段别名）须恰好出现一次；页面实时标出缺失的占位符，不合规时不能保存
- 异常：名字不存在或该提示词未启用；不合规；存储不可用；启动时任一提示词缺失或不合规则启动失败；运行中读不到或不合规时该次调用失败，按重试规则重来，不发出不合规的提示词
- 编辑：每项可撤销未保存的修改；有未保存修改时离开页面需确认；不做并发冲突检测，后保存的覆盖先保存的
- 留痕：只记名字与长度，不记正文

## 外部调用隔离

- 用途：消息收集、分析与通知所调用的外部命令（钉钉工具、codex）以最小权限运行；决策、本地模型与邮箱通过进程内网络连接调用（不经外部命令隔离），即使被消息内容诱导，也读不到本机其他凭据与文件
- 范围：外部命令只能访问自己必需的目录、网络端口与系统服务，不能读写消息库、加密的密钥文件与版本库；HTTP 客户端不跟随重定向，不读系统与环境中的代理设置；决策使用 HTTPS 或回环 HTTP，本地模型只允许回环 HTTP 与显式端口；决策接口、每个邮箱与每个外部命令可各配一个代理，代理只能是带显式端口、无认证信息的本机 HTTP 或 SOCKS5 地址；邮箱只允许加密连接，本机明文例外且不得配代理；决策只有 HTTPS 地址才经代理，经代理时仍校验目标主机的证书，代理不可用时不改为直连；配了代理的外部命令只能连该代理端口
- 异常：HTTP 地址、代理地址或环境变量配置无效时服务拒绝启动；外部命令启动自检不通过时服务拒绝启动并说明是哪条命令；运行中调用被拒绝按对应功能失败处理
- 留痕：外部调用记录渠道、会话、用户、功能、动作、请求与响应字节数、状态、次数与耗时，不记录接口地址、代理地址、密钥、消息正文、提示词、分析结果或外部响应内容；自检失败原因写标准错误
- 局限：外部命令的网络只能按端口限制，不能按域名限制；钉钉工具须读取其登录凭据；所用的系统隔离机制已被系统标为弃用；配了代理时，外部命令经代理能到达哪些目标由代理决定，代理须拒绝连往本机与内网地址，否则外部命令可经代理访问本服务与本地模型；代理能看到连接的目标主机、端口与流量大小，看不到密钥与内容；外部命令是否遵守代理设置须使用者实测；规则是否完整，须使用者在真实环境逐条验证
